# README for Assignment 4

For this project, I designed a small-scale prototype for the university's analytics platform. I designed a mini "cluster" layout and a data lake-style layout for the equipment lending data. The data holds loan records for different months of the Spring 2026 semester, with folders representing different "nodes" in a storage cluster. Additionally, there are replicas of "blocks" (files) across the nodes so the data can survive failures.

For my mini cluster, I created four nodes and used a "replication factor of 3" for each of the blocks. There are 5 blocks in total because this corresponds to the five months I created data for. I expect these blocks to grow as more and more data from different months is added. My data is also partitioned based on year and month. Even though I only have data from Spring 2026, as the data grows, this partitioning setup will help with queries. Queries won't have to look through files with multiple years and months of data within them and can instead access the specific year and month they need. This will help with speed and keeping the data organized.

My setup was that node 1 holds blocks 1, 2, 3, and 5. Node 2 holds blocks 1, 2, 4, and 5. Node 3 holds blocks 1, 3, 4, and 5. Finally, node 4 holds blocks 2, 3, and 4. Since each block has three copies across the nodes, the whole system follows a replication factor of 3. Even though node 4 only holds 3 blocks, this does not affect the replication factor because the replication factor applies to each individual block.

For my data lake layout, I partitioned my data based on year and month and copied over the data from my blocks. My data lake isn't as complicated as my mini cluster and doesn't include replication. If I were to redesign it for a real university data lake, I would separate the raw and curated data into different partitions. This way, the raw data could be referenced if needed, while the curated data could be used for analytics. Additionally, I would add validation and access controls to keep the lake clear of incorrect or unwanted data and to prevent users from accidentally deleting important data. To access the year, the partition follows this format: `year=2026`. To access the month, the partition follows this format: `month=01`.

The project layout for my mini cluster and data lake can be opened through VS Code by opening my `CST335-Week4` project folder. The Explorer on the left side of the VS Code editor can be used to view the mini cluster, including the different nodes and the blocks stored in each node. The Explorer can also be used to view the lake folder and the year and month partitions containing the loan data.

My DuckDB queries can also be run using the VS Code terminal. After opening the project in VS Code, open a new terminal and make sure it is in the CST335-Week4 project folder. From there, you are going to type `duckdb` in the terminal. This will open DuckDB and the queries in week4_queries.sql file can be run using .read week4_queries.sql. This will run both queries and display their corresponding data tables. DuckDB must be installed on the computer, and the terminal must be in the correct project folder so that it can access the SQL file and lake data.
